# tethr — 現在の設計方針

更新日：2026-09-30

## 目指す体験

ウィンドウやセッションを横断して検索し、目的の作業へ素早く戻る。そこで必要なコマンドを、履歴・候補提示・AI補完から見つける。

個人のワークフローに必要な範囲でRaycastの代わりになるツールを目指す。全機能の再現は目標にしない。現在のウィンドウ手動選択を、Emacsのように異なる種類の対象を同じ感覚で探す体験へ広げる。

## 確認した優先事項

- ウィンドウの検索と切り替え
- tmuxと[Herdr](https://herdr.dev/)のセッション検索・復帰。両者を同じ第一級の対象として扱う
- コマンド履歴検索、候補提示、AI補完、日本語の自然言語によるコマンド探索
- 未起動なら開き、起動済みなら戻るrun-or-raise

各機能の実装順序は未確定。Herdrは利用者が公式URLを示して特定した対象であり、旧文書のDeepSeek Harnessとは別に扱う。文章の推敲・翻訳は後段で検討する。

同じ第一級という位置づけは、検索・復帰の体験と優先度についての方針。tmuxとHerdrのID、状態、内部階層、操作可能な機能を同一形式へ無理に押し込めない。

## 暫定の設計案

以下は検討用の案であり、確定要件ではない。

1. 一つの検索欄から異なる対象を探し、候補の種類・状態・出所を区別して表示する。
2. 既存対象への切り替えと履歴検索はローカルで行い、AIは明示的に選んだときに呼び出す。
3. コマンド候補の選択と実行を分け、対象セッション・cwd・実行するコマンドを確認できるようにする。
4. 最初から新しいプロジェクト管理単位の登録を必須にしない。

アプリの前面化、特定ウィンドウへの移動、既存tmux paneへの復帰、コマンド実行はそれぞれ別の結果として確認する。同じcwdの新規プロセスを、既存の対話シェルの続きと同一視しない。

詳しい目的、確定事項と提案の区別、以前の方針との差分は[設計ノート](design-notes/unified-search-2026-09-30.md)に記録している。

## 先例を踏まえた検討

異種候補の一括検索、履歴の文脈検索、AIによるコマンド提案、セッション内の検索・復帰には既存の先例がある。これらを単体でtethr独自の価値とは扱わない。

検証したい仮説は、Ghostty・tmux・Herdrなど普段使う環境を保ちながら、外部のウィンドウやセッションを横断して探し、目的の作業へ戻る負担を減らせるか、という点にある。先例との比較と設計への示唆は[AIターミナル・ランチャー調査](research/ai-terminal-precedents-2026-09-30.md)を参照。

## 実装と技術選定の状態

Native / Tauri / OpenTUIの三つの比較試作がある。採用スタックは未決定。

[比較試作レポート](research/prototypes-2026-09-12.md)には、共通Swift helper、試験用シェルの継続、試験用アプリのrun-or-raiseの確認が記録されている。現在の横断検索や任意セッションへの復帰が完成したことは示していない。過去の合格はその試験条件に限り、現在の実機で再検証した結果ではない。

実IME、グローバルホットキー、個別ウィンドウや既存paneへの安全な復帰・入力、エージェント連携には未確認事項が残る。UI方式は、同じ対象を探して戻る一往復の快適さと、失敗を観測・再検証できるかで比較する。

## 次の判断

ウィンドウ／tmux／Herdr検索かコマンド履歴検索のどちらを最初の一往復として試すか選ぶ。Herdrの公式CLI・socket APIは確認できたが、利用環境での接続とmacOSの窓への復帰は未検証。CLI接続から試し、継続更新が必要ならsocket購読へ進む案とする。候補の識別、消えた対象への対応、実行確定、日本語IMEの扱いを具体化する。AIに送る情報と費用の扱いも、補完の導入前に決める。
